# Storage 0.64 notes

## [0.64.0] - 2026-11-02

### ⚠️ Breaking

- Return typed codec/collection errors, including fallible map/set iteration and
  lazy value decoding. Require an explicit byte ceiling for cell loading.
- Protect cell/vector payloads with checksums (`ICCELL01` / `ICVECC01`). Reuse
  inactive directory arenas (`ICROOTR1` / `ICDIRR01`) and coalesce contiguous
  allocation growth. This extends the pending fresh/reset-backing hard cut.
- Extract the AVL deletion successor in one traversal. Native tests cover
  read-only error paths, repeated arena reuse and interrupted reuse/reopen.

The repository is now IC Storage. Its adapters are `ic-logging-storage` and
`ic-metrics-storage`; the release groups are `storage`, `logging-storage` and
`metrics-storage`. Update dependencies/imports and release automation using
[the naming adoption guide](../../docs/migration/storage-naming.md). Existing
versions and historical receipts are not relabelled.

Storage now owns allocation, backing interfaces, codecs and all supported
collections. Remove direct `ic-memory` dependencies and import runtime/key/lease
APIs from `ic_storage`. The persistence release group publishes Storage only;
Metrics Storage and Logging Storage require their matching pending minor releases.

Remove `ic-stable-structures` completely. Map, Set and map regions share an owned
AVL ordered-tree engine with reusable blocks and staged node updates. Vector
uses fixed-stride bounded slots; Cell owns its cached value and writer. Their
supported names remain `StableBTreeMap`, `StableBTreeSet`, `BTreeMapRegion`,
`StableVec` and `StableCell`. Stable Log, Min-heap, `LogIter` and `LogWriteError`
are removed because no sibling application use was found.

The fixed-slot manager and separate ledger are replaced by the owned Wire
allocation directory. `StorageConfig` replaces bucket geometry; `AllocationGrants`
replaces numeric pools; `allocation_id` returns an opaque u64 identity. Hosts
supply namespace grants and checked names, never memory IDs. Historical names
retain ownership when omitted but need current admission before opening.
Policies validate keys without numeric-slot arguments. Repeated/cold admission
that adds no names performs no directory write or generation increment.

This is a retained-data hard cut. Previous manager, ledger, map, set, vector and
region images are unsupported. Hosts must use fresh backing or explicitly retire
the complete previous image. There is no compatibility decoder or automatic
reset, and resetting governance alone is prohibited. `Storable`, `Bound` and
`Memory` now have Storage-owned identities. Primitive numeric encodings are
little-endian. IcyDB region admission must recognize `ICMAP001` instead of its
former upstream framing. Application Wire record schemas remain caller-owned.

### 🧹 Cleanup

One runtime owns namespace admission, durable names, sparse exclusive leases and
extent translation. Backing custody survives detached leases. Logical reads and
writes trust exclusive custody between checked boundaries; failed backing IO
poisons the shared owner. Cold directory reads never initialize replacements.

Wire roots and node records have explicit resource ceilings and corruption
checks. Collection updates admit codecs and reserve capacity before writes.
Native writes remain nontransactional; installed Wasm traps use host rollback.
Directory commits reuse protected inactive snapshot arenas; application extents
and abandoned tails remain unreclaimed. Full snapshots are still written. Map
scans retain pointer cursors but still read complete node
records. Existing-key replacement skips unchanged ancestors, and allocation IO
uses derived extent indexes with contiguous IO within each physical extent.
These are correctness-qualified implementations, not claims of
performance equivalence with the removed substrate.

The supported collection surface is narrowed to observed sibling use: map
`pop_first`/`pop_last` and set `first`/`last`/`pop_first`/`pop_last`/`range`/`clear`
are removed. The unused raw Cell payload decoder is removed; envelope admission
and the header-size constant remain public for existing consumers. Cell marker,
version and payload-offset constants are private implementation details.

Directory commitment no longer serializes and decodes its own private candidate.
Final preparation still enforces the receiving owner's structural and Wire
budgets before backing mutation, while recovery and checked-boundary validation
continue to decode stored bytes. Allocation-ID lookup uses the existing index
without cloning all diagnostic rows. Lease tests now use production construction
and typed growth instead of separate test-only modes and a second Memory adapter.

### 🧪 Testing

Add `make benchmark-storage`: matched installed Wasm map operations against
DFINITY's `ic-stable-structures`, with model-checked results, raw samples and
instruction ratios. The upstream dependency stays in the independent benchmark
graph. See the [methodology](../../qualification/ic-storage-benchmarks/README.md)
for measurement boundaries and reproduction.
The matrix also covers scalar `u64`/`u128`, fixed 32-byte keys/values, string
keys/UTF-8 values and a structured Wire record, using concrete typed maps and
type-labelled output. Input preparation and result normalization are outside timing.

Native coverage includes 1,024 bindings/live leases, multi-page directories,
interleaved extent IO, custody, retained-name admission, interrupted writes,
corruption, reusable tree blocks, mixed-direction range scans, vector reopening,
collection growth refusal and Metrics/Logging checkpoint continuity. Installed
qualification covers all five collection types across 1,031 named allocations,
upgrade/rollback, checked metadata faults and Logging restoration. The three
development archives and their native/Wasm consumer also qualify.
