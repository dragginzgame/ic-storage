# Storage 0.72 notes

## [0.72.0] - Unreleased

### ⚠️ Breaking

`open_memory` uses the directory admitted by its continuously claimed runtime
without reading backing metadata. It still requires current admission, a healthy
owner and an exclusive lease. Raw metadata changes after admission are no longer
detected merely by opening a handle. Hosts and fault-injection tests needing an
explicit integrity check must call `diagnostics()` or `memory_allocations()`.

Cold reconstruction, initial bootstrap, new binding commits and explicit
diagnostics retain full integrity checks. Native backing failures still poison
the shared owner, while IC executions retain rollback. Bounds, grants and backing
custody are unchanged. The stored format is unchanged: no migration or reset is
required. This minor line records the changed detection guarantee.

### ⚡ Performance

Ordinary opening no longer repeats population-wide verification. There is one
opening API; the unpublished batching API and name-checksum cache were retired
before release. Vector Push/Pop also write their already allocated length header
directly, preserving payload-before-length publication.

See the [matched study](../../docs/audits/recurring/storage-vector-batch-2026-11-10.md)
for measurements, rejected experiments and qualification scope.
