# Storage 0.68 notes

## [0.68.11] - 2026-11-08

### ⚡ Performance

Remove the directory's derived ID-to-position B-tree; binary-search the existing
strictly ordered entries instead. Keep key lookup, ID validation, custody and
snapshot publication intact. Minimal Map Wasm drops 137,262 → 134,314 bytes;
all-five drops 153,001 → 150,062 bytes (ICSS: 90,264 / 119,378). Compact-loop timing
is mixed, including a 7.60% Set regression, so this is a size/simplicity tradeoff.
Sparse-ID regression tests and installed IO/upgrade/rollback qualification pass.
See the [comparison and limits](../../docs/audits/recurring/storage-wasm-gap-2026-11-08.md#removing-the-redundant-id-index).
No consumer migration is required.

Use one private tree-memory type for ordinary maps and bounded regions so equal
key/value types reuse compiled B-tree code. Whole maps still own their admitted
lease; region operations retain their existing Rc temporarily and reload current
roots. Bounds, reservations, poisoning and owned snapshots remain unchanged.
Full comparison Wasm drops from 14,308,122 to 11,719,033 bytes; the smaller Storage
consumer fixture drops from 191,499 to 182,316 bytes. The shared memory dispatch
costs up to 6.90% in the measured Map loops (Set up to 3.37%, regions up to
4.67%; Cell/Vector unchanged), documented in the [size audit](../../docs/audits/recurring/storage-wasm-gap-2026-11-08.md).
No public API or stable-image migration is required.

### 🔧 Tooling

Adopt committed Shared Tooling 0.31.10 and published IC Build 0.79.0, including the
matching release metadata editor. Formatting selects only owned Cargo workspace
members; LOC module depth uses `CLOC_DEPTH` or `cloc.sh -d`. The shared hashing
review and publication-impact rules are adopted without changing stored hashes,
production APIs or package versions. CI restores/saves the shared authenticated
download cache and runs one full-history secret scan outside host matrices and
release flows. CLOC also accepts crate/module selectors. Existing benchmark work
remains pending.

### 🧪 Testing

Add `make benchmark-storage-size` with separate unpublished Storage and ICSS
consumer crates, common minimal endpoints, eight feature selections and stripped
size-profile builds. Keep the model/runner outside both Wasm graphs. All 16
artifacts pass 1,888 checked calls and 32 upgrades. Map-only sizes are
137,262/90,264 bytes; all-five sizes are 153,001/119,378 bytes. These are the primary
small-application size controls; the full type catalogue remains a separate
instruction/correctness benchmark. No production API or image changes here.

Use published ICSS 0.7.2 directly in the unpublished comparison workspace,
removing the old Platform 0.17 reference facade. Preserve the single modified
production engine source for each supported collection; Set and regions continue
to share the B-tree. No production dependency or collection behavior changes.


Add a compact benchmark build for matched Wasm footprint investigations without
changing the full type catalogue or production collections. Compare ordinary
and size-oriented compiler profiles, including ICSS on governed Storage backing.
The [investigation](../../docs/audits/recurring/storage-wasm-gap-2026-11-08.md)
identifies repeated tree specializations and fixed governance costs; Storage
remains larger than ICSS. No size-parity or production optimization is claimed.

This removes temporary allocations from borrowed collection writes without
unsafe code, changing decoders or changing owned-encoding APIs. Stored bytes,
resource governance and collection formats are unchanged; no migration is needed.

this is not an application-size measurement. The
[codec study](../../docs/audits/recurring/storage-byte-codecs-2026-11-07.md)
records the broader matrix, tradeoffs and comparison with published ICSS 0.7.2.

the same workload arguments as ordinary runs. Bounded read-probe restrictions
and refusal to mix diagnostic modes remain intact.

## [0.68.6] - 2026-11-07

### ⚡ Performance

Skip the final B-tree overflow-pointer rewrite when the chain already has the
correct terminator. Shrinking chains still publish a new terminator after
reclaiming unused pages. Map, Set and map regions benefit without changing
allocation geometry, stored bytes or public APIs; no migration is required.
Also skip backing calls for empty fields inside an already allocated node page,
preserving logical extent and overflow reservation. Set's zero-byte values gain
most; physical backing IO and page footprints remain unchanged by this shortcut.
Return empty values directly from the shared lazy-value loader, avoiding payload
reader setup while preserving ordinary key, routing and nonempty-value reads.
Avoid duplicate insertion searches after a non-full root miss; retain the
pre-split lookup for full roots. This step improves 104 depth handler cells,
leaves 608 unchanged and adds 660 bytes to benchmark Wasm.

Together, matched depth measurements improve 368 of 712 whole-handler cells,
with the other 344 unchanged, and remove 8,358 bytes from the complete benchmark
Wasm versus 0.68.5. The largest handler saving is 11.35%. The empty-write step
alone regresses six cells by at most 0.013%; the later empty-value step improves
368 cells without regressions. These are synthetic workloads, not universal
application gains. The [IO study](../../docs/audits/recurring/storage-btree-io-2026-11-07.md)
and [empty-value study](../../docs/audits/recurring/storage-empty-values-2026-11-07.md)
record comparisons against published ICSS 0.7.2 and rejected read-path variants.
The [save/search study](../../docs/audits/recurring/storage-save-search-2026-11-07.md)
records the retained root lookup and rejected overflow-list transfer, including
matched 64-KiB/1-MiB payload results. Fewer allocations did not justify its regressions.

## [0.68.4] - 2026-11-07

### ⚡ Performance

Transfer the existing lazy-key read buffer into owning decoders instead of
borrowing it and forcing String/byte-vector codecs to copy it. A compile-time
destructor check preserves the existing borrowed path for scalar and fixed-array
keys. Eager keys retain their shared buffer; no new tuning option, cache or
retained-layout change is introduced. No migration is required.

The matched 256-record ordered matrix checks 10,476 calls per run. Selected
full synthetic handlers improve by 3.9% for string Map Get, 4.5% for Replace,
1.5% for a 128-entry string scan and 5.2% for string Set Get versus 0.68.3.
All four are cheaper than published ICSS 0.7.2 in this matrix. Integer/fixed-byte
controls are unchanged; five no-op control cells rise by less than 0.10%.
The [backing study](../../docs/audits/recurring/storage-icss-backing-parity-2026-11-06.md)
retains the rejected unconditional trial and both timing scopes. These are
synthetic workloads, not complete application endpoints or universal speedups.

Map/Set iterator `last()` now selects the last remaining entry through the
existing reverse cursor. Bounded ranges and consumption from either end retain
their successful results. Keys/values projections and direct last-entry APIs are
unchanged. In the matched 256-record matrix, selected full handlers with 32
iterator-last queries use 85–94% fewer instructions than the pending key-buffer
baseline and 86–95% fewer than ICSS 0.7.2. The worst other stateful-trace handler
increases 2.24%; the complete type-harness Wasm grows 2.1%. These are measured
tradeoffs, not a universal collection speedup or a production-canister size estimate.

### 🩹 Fixed

Vector iterator `last()` uses its final remaining live index instead of scanning
the population. It preserves forward-iteration results after front/back
consumption, shrinking and appending, without changing stored bytes or public
types. Like direct skips, it reads and decodes only the returned record, so it
does not validate discarded records. Published ICSS 0.7.2 retains the full scan.

Map reopening and operation-local region views admit the current framing from
the same header read used to restore the root. Eliminate the separate 12-byte
read without caching stale roots, initializing foreign images, or changing
typed framing rejection. Invalid internals still follow the existing trap policy.

### ⚡ Performance

Vector direct reads use a stack buffer for fixed-width values up to 32 bytes
without destructors. Larger, variable-width and destructor-bearing values keep
owned decoder input; collection layouts and public APIs are unchanged. Against
the immediately preceding Storage implementation, uniform batches of 32 save
6,400 instructions for both u64 and fixed-32-byte reads, including at the full
synthetic handler boundary (about 0.8–0.95%). The 15-type matrix covers all 13
Vector operations; cutoff/reopen and owned-decoder tests cover the new path.
These are workload-specific results, not an application throughput claim.

Resolve each lease's directory index once on admission, using the directory's
append-only entry invariant. Keep extent walking outside the inline cache-hit
path. Regions check their static namespace while the underlying lease admits
the complete live range, eliminating a repeated lookup without weakening bounds.

The copied engines retain ICSS's direct reads into uninitialized buffers through
`Memory::read_unsafe`, following ICSS's destination and initialization contract.
Existing custom backings retain a default through their ordinary read method;
overrides can avoid zeroing bytes that IO overwrites. Collection APIs remain
safe. Fragmented reads, native poisoning and empty-range behavior retain the
governed contract.
The Wasm fast path selects published Platform Runtime >=0.19.4 for its
`stable64_read_uninit` export, with only `ic0` enabled. Both maintained workspaces
adopt that minimum; the qualifier's exact Runtime guard follows its selected version.
[Backing comparison and qualification](../../docs/audits/recurring/storage-icss-backing-parity-2026-11-06.md).

## [0.68.0] - 2026-11-06

### ⚠️ Breaking

Replace all collection engines with private copied ICSS 0.7.2 source: B-tree,
Set over that B-tree, fixed-stride Vector, cached Cell and governed map regions.
Keep Storage's allocation directory, custody checks, existing application codecs
and successful-call API shapes. There is no production ICSS dependency or ICSS
MemoryManager. [Provenance and adaptations](../../docs/storage/upstreams.md).

Every prior Storage collection image requires an explicit host rebuild/reset or
fresh admitted allocation. Current framing is BTR2 (explicit page size), SVC1 and
SCL1. Hosts must update collection/region framing admission. No legacy reader,
implicit conversion or automatic reset exists. Directory encoding is unchanged.

Inside collections, malformed codecs, engine state and allocation failures now
trap, including operations whose successful-call API still returns Result.
Explicit framing admission and page reservation retain typed failures. Native
mutation panics may leave partial bytes and poison the shared owner; discard its
runtime and leases. IC execution rollback remains the Wasm atomicity mechanism.
There are no collection checksums; application validation cannot detect every
valid-looking byte change. Cell retains its caller-selected load ceiling.

### 🔧 Changed

Delete the prior independent tree/block allocator, record envelopes, node cache,
Vector scan windows, cached length and mutation epochs. Preserve one algorithm
implementation behind the public governed adapter layer. `set_node_cache_budget`
remains a ceiling hint satisfied by the baseline's zero cached bytes, not a cache
enabler. New benchmark runs reject positive Storage cache budgets.

Storage primitive codecs are unchanged. In particular, unsigned encodings differ
from ICSS's default codecs; exchanging images requires matching application
codecs and bounds. Six same-image tests explicitly match those codecs and
exchange updates with separately published ICSS across all supported forms.

The earlier checksum-free ICVEC002 experiment and its measurements remain
historical controls. They do not measure this baseline or establish its speed.
