# Storage 0.71 notes

## [0.71.0] - Unreleased

### ⚠️ Breaking

- Replace snapshot-directory allocation with an ICSS-derived bucket backing.
  Existing whole-store images require explicit host retirement/reset or fresh
  backing; incompatible nonempty images are rejected without writes. There is no
  migration reader or automatic reset. Named opaque IDs, grants, exclusive leases
  and collection APIs remain governed by Storage.
- Remove `StorageConfig::wire` and the retired directory Wire error; IC Wire is
  now only a development dependency of core Storage. Allocation
  controls now use explicit checked rows. `extents` limits eight-page buckets;
  creation-time allocation/bucket table capacities cannot grow within an image.
  Default control reservation is 960 KiB and the default bucket ceiling permits
  8 GiB of data reservation. Physical-page limits include metadata and slack.
- Native interrupted metadata writes fail closed instead of recovering the old
  snapshot. IC executions retain rollback. Growth checks budgets/refusal before
  control writes and trusts exclusive custody rather than rereading all metadata.
  Hosts must review [the allocation contract](../../crates/ic-storage/ALLOCATION.md).

### ⚡ Performance

- Transfer the consumed Vector `last()` buffer into its decoder. Large-byte
  terminal reads improve 32.6–41.7% in the matched inner loop; whole-handler gains
  confirm the saving. Scalar/array controls add 5/12 instructions per result.
  Other measured operations remain unchanged; broad harness Wasm shrinks 2,647
  bytes and small-consumer controls are byte-identical. See the [comparison and
  scope](../../docs/audits/recurring/storage-vector-last-2026-11-09.md).
- The bucket backing removes snapshot rewriting and reduces the matched small
  Cell consumer by 14,840 bytes and all-collection consumer by 14,630 bytes.
  Depth and bulk results are mixed; whole-handler Cell growth improves while
  shrink is effectively unchanged despite a higher inner-loop count. Whole-handler
  Vector Get/Pop are nearly unchanged and Push improves; 64-KiB iterator cases
  regress by 1.4–2.8% and remain an attribution follow-up. See the [complete matrix
  and limits](../../docs/audits/recurring/storage-bucket-backing-2026-11-09.md).
- Avoid redundant Cell header and capacity work when the encoded length is
  unchanged. Same-length replacements write only the payload; empty-to-empty
  replacements need no writes. Stored bytes and public APIs remain unchanged.
  Before the backing hard cut, the isolated 73-type comparison showed gains
  with at most 21 extra instructions on size-changing operations; its small Cell
  consumer grew 170 bytes. These are not combined-change results. See the
  [measured tradeoff](../../docs/audits/recurring/storage-cell-length-2026-11-09.md).
- Initialize each new B-tree overflow page with one combined header write.
  The isolated pre-backing comparison improved matched large-value cases by up
  to 1.02% with no regressions; stored
  bytes and public APIs are unchanged. Broad benchmark Wasm grows by 16 bytes,
  and the small all-collection consumer grows by 83 bytes. See the
  [comparison](../../docs/audits/recurring/storage-overflow-init-2026-11-09.md).

### 🔧 Tooling

- Adopt published Toko Tooling 0.36.1 in both workspace catalogs and lockfiles;
  refresh the authenticated snapshot for corrected test-closure CLOC attribution.
- Extend bounded read/allocator diagnostics to every operation in the Vector bulk
  shard. Preserve overflow rejection and keep diagnostic probe costs separate
  from production instruction comparisons.
- Add Cell growth attribution coverage comparing both engines over governed
  backing and ICSS's own manager, including shrink/regrowth without allocation.
  Keep performance attribution separate from native IO counts. The subsequent
  backing replacement is the explicit format change described above.

- Give both Wasm size consumers ordinary, crate-owned endpoint modules and
  reject differing endpoint sources before comparisons. Remove cross-crate
  module path overrides without changing the benchmark protocol.
- Adopt IC Build 0.81.0 with its matching release-metadata editor and IC Host
  Artifacts/FS/Process 0.76.1 for native repository tooling. Storage's production
  APIs and stored formats are unchanged; this maintenance alone does not require
  a product release.
