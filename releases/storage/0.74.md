# Storage 0.74 notes

## [0.74.1] - 2026-11-14

Pre-freeze registry review on 2026-11-14 confirms the locked first-party
selections are current: Toko 0.43.0, Testkit 0.104.0, Build 0.84.1, Host
Artifacts/FS/Process 0.77.2, Wire 0.22.1, Logging 0.25.5, Metrics 0.30.5,
Platform 0.32.2, Runtime 0.22.2 and Types 0.20.2. Keep compatible catalog
requirements. The independently selected recovery editor remains Build 0.84.0;
its optional 0.84.1 CLI refresh is deferred to the next tool-maintenance batch,
preserving the qualified editor for this release. The release gates qualify
the captured locks; no additional supplier update is made during delivery.

### 🧹 Cleanup

Use Rust 1.100's standard scope guard for native backing IO poisoning, retaining
the same scope and unwinding-only condition. Successful IO leaves the owner healthy; native
unwinding poisons it before reuse. This code remains excluded from Wasm builds.

### 🧰 Tooling

Adopt IC Wire 0.22.0 for key serialization tests, diagnostic size probes and
independent qualification protocols. Core Storage's production graph remains
Wire-free. Adapter public codec-error changes have their own minor release notes.

Adopt published Testkit 0.104.0 for independent qualification and the managed
server CLI. PocketIC remains 16.1.0 with the existing polling and lifetime budgets.
Its published requirements align the qualification graph with Host 0.77,
Platform 0.32 and Types 0.20, removing the previous Platform/Types duplicates.
Product dependencies and public Storage types are unchanged by this adoption.
The 0.104 update removes unused Testkit Wire helpers; Storage already owns its
qualification protocols and needs no caller migration. Only Testkit's entry
changes from the preceding qualification lock selection.

Adopt authenticated Toko Tooling 0.43.0 and offline `make deps-list`. Apply the
common Cargo lint minimum and stricter Rustdoc tables in both workspaces. Remove
unused display aliases and shared metadata while preserving all release members.
Place example-only Metrics dependencies in the qualification dev graph and
exercise actual Platform/Runtime identity exchange. Document that isolated native
test dependencies and optional upgrade failures do not block a qualified release;
real type/executor conflicts and required integration tests remain blocking.
Project qualification dependencies by package ownership rather than root alias
names, and include Metrics Storage in catalog/lock updates and rollback tests.
The released bootstrap correction admits complete release membership without
unused aliases. The binary-only runtime qualifier uses the supported source-only
tooling marker, retaining strict dependency linting without dummy imports.
Install shared executables under `vendor/toko-tooling/` and migrate Make, CI,
hooks and release-helper callers together. Select release/publication explicitly
and retain the consumer-owned compiler pin. Validation runners receive the
consumer root explicitly. Retire the producer-only generic fixture selection;
retain product gates and native release/recovery qualification.
Adopt Cargo-tool maintenance recovery that reuses an admitted executable when
retrying retained scratch cleanup.
Adopt the vendor-aware retention probe from
[Toko #381](https://github.com/dragginzgame/toko-tooling/issues/381), preserving
consumer-root semantics and existing failure/completion assertions.
Resolve hook execution and installation paths independently of inherited
`CDPATH`, fixing the hook fixture failures that stopped release validation.
Replace the retired `make cloc` interface with the `toko-cloc` PATH launcher;
use `--manifest qualification/Cargo.toml` to select the independent workspace.
See [the adoption record](../../docs/adoption/storage-tooling.md#toko-0430-adoption)
for consumer validation.

Adopt published Host Artifacts, FS and Process 0.77.0. Build 0.84.0 is required
because the archive qualifier exchanges Host `OutputLimits` with Build's API;
mixing Build 0.83 and Host 0.77 fails compilation. Align the selected metadata

do not enter product Wasm. The Testkit 0.102.0 adoption also selects Host 0.77
through its own published requirements in the independent graph.

Consume Build's typed build/environment compiler-override observations. Release
qualification refuses both Cargo sections before effects, reports their field
names and source paths, and keeps configured values private. Regression coverage
includes direct/included configuration, empty values and forced relative values.

Correct the independent qualification catalog's Metrics Storage requirement from
0.76.2 to the local 0.77.0 package. The previous minor release advanced its package
but left that stale compatible-old-line requirement behind, preventing Cargo
resolution of the independent workspace. Preserve the pending Metrics 0.30.1 lock
selection and select Logging 0.25.1 in both catalogs and locks.

No collection behavior, stored format, release policy or product version changes.

## [0.74.0] - 2026-11-13

### 💥 Breaking

Require Rust 1.100.0 for consumers and for development/release builds.
Collection APIs and retained formats are unchanged; no data reset is required.
Adopt the common compiler and lint policy from [#159](https://github.com/dragginzgame/ic-storage/issues/159).

### 📦 Dependencies

Adopt published Platform Runtime 0.22.0 for Wasm stable-memory IO and Platform
0.32.0 for the independent composition fixture. Production still selects only
Runtime's `ic0` feature; native Storage has no Platform dependency. Both locks
select Logging 0.25.0 and Metrics 0.30.0 for their owning adapters.
No stored format, allocation policy or collection algorithm changes.

The pre-freeze registry review confirms Toko 0.40.1, Build 0.83.0, Host
Artifacts/FS/Process 0.76.5, locked Wire 0.21.5 and Testkit 0.101.0 are current.
Testkit retains its published Platform 0.31/Types 0.19 native client graph;
the separate composition fixture selects Platform 0.32/Types 0.20 with Runtime
0.22. No shared runtime or public value crosses those independent consumers.
PocketIC remains 16.1.0. No unrelated supplier upgrade is included.

### 🧰 Tooling

Select published Toko Tooling 0.40.1 in both workspace catalogs and lockfiles,
with the authenticated installed snapshot and matching pin exceptions. Existing
entrypoints, executable files and tool pins remain. Independent runtime CI also
lints its native/Wasm qualification graph and rejects growth in enumerated private
protocol documentation debt. Root library gates retain their graph boundary.
The release-group detail-note selections follow the pending minor lines, and
deployment guidance identifies existing receipt reuse and unsupported collector recovery.
See [the adoption record](../../docs/adoption/storage-tooling.md#toko-0401-adoption).

### 🧪 Testing

The full-identity Map workload now measures the second lookup separately from
the cold first lookup and third lookup. Each phase has its own execution, with
zero, one or two untimed pre-reads of the same key. Both Storage and ICSS use
the same protocol and model checks at 1k/10k/100k records. This supports
[#158 — Evaluate routing-key locality and blob density](https://github.com/dragginzgame/ic-storage/issues/158);
it does not establish a consumer authentication speedup.

Stable-read diagnostics now capture single-result Map rank cursors and can
restrict trace collection to batch/scan limit one without changing the workload.
The injector recognizes Binaryen's explicit function-type annotations while
retaining unique-symbol and bounded-trace admission. These are host diagnostic
changes; product Wasm, collection behavior and stored formats are unchanged.
