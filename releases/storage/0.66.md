# Storage 0.66 notes

## [0.66.3] - 2026-11-04

### ⚡ Performance

Map/Set node caching now uses two slots per set, with least-recent replacement
among eligible nodes and the existing protection for roots and their immediate
children. Colliding ancestors and descendants can both remain warm. The address
hash and accounting of cached node-buffer bytes are unchanged; the table rounds
down to complete pairs, disabling caching when the budget cannot admit two slots.
Cache limits remain explicit and persisted formats/public APIs are unchanged.

Matched 4,096-record baseline-allocator growth traces improve by up to 26.89%,
with up to 1.20% complete-trace regressions. Cold-per-call Map/Set controls range
from −0.60% to +1.50%; the largest non-control individual regression is +4.25%.
The separate retained64 allocator experiment's selected 61% regression is removed,
but that allocator is not adopted. The cache costs up to 2.04% more on its other
warm traces. Five installed runs validate 9,408 calls; two seeds and a 64 KiB
cache do not establish universal gains. See the
[two-way investigation](../../docs/audits/recurring/storage-icss-hotspots-2026-11-04.md#two-way-cache-experiment-and-the-icss-comparison).

Inline-to-inline Map replacements now copy unchanged encoded spans into one
checksummed node frame, preserving staged publication and returned-value validation.
In a matched 256-row Uniform/Hot16 comparison, single replacements use 3.74–7.47%
fewer instructions and batches of 32 use 19.53–26.60% fewer. Sharing existing
replacement preparation reduces the first candidate's added module bytes by 56%.
The selected comparison Wasm grows by 4,054 bytes overall (3,893 code bytes).
One unrelated Last case regresses
2.66%; stable-page counts are unchanged. These scope-limited measurements do not
claim a universal speedup. Public APIs and persisted formats remain unchanged.

Map and Set iterators decode keys by borrowing the already validated node buffer.
They no longer allocate a temporary encoded-key vector before scalar/array decoding.
Key bounds, node checksums, range admission and double-ended traversal remain.
A matched 64-record sequential run (one sample, three rounds, disabled caches)
reduced 32-key `Set<u64>` scan instructions from 146,138 to 134,628. Key-only scans also skip unused inline values; combined
32-byte-array Map KeysScan falls from 197,267 to 167,727 (15% fewer). This second
change increases Set scan costs by 0.3–0.6% versus the first candidate; final
String Set scanning improves about 0.2% versus the original baseline. Two non-scan Map rows increased by less than 0.4%; no universal
speedup is claimed. See the [hotspot investigation](../../docs/audits/recurring/storage-icss-hotspots-2026-11-04.md).

### 🔧 Tooling

Private Metrics/Logging implementation PRs now use the same qualified group
selector as releases, against the exact tested merge commit. Lint, feature,
rustdoc and Wasm stages select the admitted adapter package; dependencies still
compile. Unknown/public/core/shared changes and non-docs pushes keep full checks.
Workspace archive integration, policy checks, all native hosts and installed
runtime qualification remain required. CI retains source-bound plans/timings and
still produces its native failure-evidence upload fixture. No total timing gain
or hosted acceptance is claimed from local qualification.

### 🧪 Testing

The native shared-backing example's `--small-records` selection measures four
1,024-row maps around small external-value size boundaries, including metadata IO
and six delete/reinsert rounds. Smaller-allocation prototypes remain research:
they save capacity for small values but increase growth costs and require an
explicit format transition. The released allocation minimum remains unchanged.
A deeper four-policy investigation adds explicit payload selection, repeated
small/grown reads and updates, 24-phase native histories with cold reopening,
and 16,384-record cache controls. All 39,168 installed calls pass. Capacity
retention improves selected batch histories but regresses a warm single-record
trace by 61%; research patches and per-round evidence are retained, not adopted.

The default comparison now covers 29 concrete cases and 52 type/size combinations,
including bounded byte vectors. An opt-in `boundaries` recipe exercises twelve
adjacent payload sizes across Map, Vector, Cell and Region, with shuffled
population and three mutation rounds. Sequential access adds nearby-key locality
and population wraparound while keeping missing keys disjoint.

Both engines receive the same logical traces and canonical codecs. The benchmark
retains result, length and final-content verification. ICSS's bounded vector slots
still reserve their declared 1 MiB maximum; matching payloads do not imply matching
layouts. Reverse Set iteration remains excluded because ICSS 0.7.2 lacks the
matching iterator contract. No collection API, default allocation policy or
persisted format changes. Per-round summaries distinguish initial-population costs
from subsequent mutated states, including Cell reads after Shrink. See the [comparison guide](../../qualification/ic-storage-benchmarks/README.md).

## [0.66.2] - 2026-11-04

### 🔧 Changed

- Decode `MapEntry::value()` from borrowed encoded bytes after bounds admission,
  avoiding Storage's intermediate clone. Consuming entry methods retain owned
  decoding. No public signature, durable format or consumer migration changes.
- Extend generated histories across external-value size classes and combine
  variable keys, changing payload sizes, deletion, cold reopening and cache
  collisions. Extend matched shared-backing runs with six size-changing rounds.
- Correct bulk growth coverage: 64 KiB grows to 256 KiB and 1 MiB to 1.5 MiB.
  Qualify framed replies against IC's 2 MiB ceiling as well as Wire budgets.
  Earlier same-size bulk Grow rows remain historical evidence, not comparable
  growth measurements. See the [ICSS re-audit](../../docs/audits/recurring/storage-icss-hotspots-2026-11-04.md).

- Adopt Shared Tooling 0.29.4 (`628ccc7`), retaining the earlier UTF-8 evidence
  qualification and adopting test-layout, Metrics ownership and group-ledger
  guidance. Export committed bytes from the verified clean source checkout.
- Guard retained Git-side release state before and around release steps; preserve
  evidence on refusal. Dependency-adoption evidence now stays under `target/`.
- Move 17 inline test modules, two adapter test files and private fixture helpers
  into `tests.rs` or `tests/` using ordinary discovery. Benchmark binary wiring
  uses `tests/driver.rs` because the library owns the root `tests.rs` module.
  Small cache instrumentation remains beside its observed methods. No production
  visibility, API or persisted-format change is required.
- Keep CI-selection fixtures under `target/ci-selection/`. Qualify the updated
  classifier through the actual workflow caller; its optional root-VERSION
  exception stays disabled for this Cargo workspace. Metrics Storage remains the
  owner of governed metric snapshots, and root changelog navigation stays intact.

- Move eleven remaining shell-fixture defaults into workspace `target/fixtures`
  and Rust release-helper fixtures into `target/repo-tool-fixtures`. The native
  group-plan fixture follows Cargo's selected target directory. Exclusive names,
  failure retention and caller-selected evidence paths remain; retention checks
  still exercise explicit relative aliases and child-tool TMPDIR behavior.
- Refresh the active audit overlay to reference current admission, backing
  custody, directory publication, leases and collection engines. Replace retired
  source paths and the old compiler command with Rust 1.99.1 and scoped checks.
  Historical audit reports and their source identities remain unchanged.

- Select eight-page buckets for the ICSS research comparison by default after
  matched 1/8/128-page measurements; retain explicit stock-128 and low-memory-1
  controls. Storage's production allocation policy is unchanged.

- Add a native shared-backing experiment for 32/64 allocations, mixed record
  sizes, interleaved growth and repeated churn, plus controlled external-value
  allocation-boundary probes. Keep production geometry and defaults unchanged.

## [0.66.1] - 2026-11-03

### 🔧 Changed

- Load the release stage catalog from admitted source at runtime, preserving
  standalone bootstrap and archive builds without embedding repository-root files.

- Qualify the native Rust group-proof collector and retained-proof recovery
  against real Shared runner/verifier evidence, including failures and tampering.
  [#156](https://github.com/dragginzgame/ic-storage/issues/156).

- Adopt Shared Tooling 0.28.2 (`5cf67f8`), centralize group evidence and
  baseline observation, and derive full dispatch from one stage catalog.
  Preserve release projection recovery, existing proof and pending work.

- Add consumer-informed `control`, `records` and `bulk` benchmark recipes,
  including byte vectors and opt-in 64 KiB/1 MiB records. Record sibling memory
  declarations and sizing boundaries; production defaults remain unchanged.

Release validation adopts Shared Tooling’s group-plan runner. Private adapter-only
changes can omit unchanged core/peer tests and release-tool fixtures; public,
shared, dependency and core changes retain the full gate. Repository CI, native
hosts, installed runtime duties and archive integration remain unchanged.

Schema-2 validation receipts bind the selected source, previous release baseline,
plan, input checkpoint and successful stage evidence. Missing or changed proof
refuses recovery; historical full-gate receipts stay with their original helper.
This changes contributor release tooling, with no library API or stored-format
change. See the [selection contract](../../docs/validation/storage-release-validation.md).

## [0.66.0] - 2026-11-03

### ⚠️ Breaking

Adopt published IC Wire/Derive 0.16.0 in the root and independent runtime
workspace. Public codec errors and `StorageConfig::wire` now carry Wire 0.16
Rust types; consumers exchanging these values must align their direct dependency.
Storage does not select Wire’s optional Platform Account schemas. Directory and
collection framing, record bytes, limits and reopening contracts are unchanged;
this adoption requires no backing reset or stored-data migration.

### 🔧 Changed

Adopt committed Shared Tooling 0.27.29 at `18e727032237e4a6540fefce66bb1b90beb31644`.
Lasting work stays in the requested checkout or an explicitly authorized durable
contribution location; temporary validation copies cannot hold unique implementation.
Direct integration-branch pushes and alternate delivery checkouts require explicit
authorization, including when the release configuration defaults to direct delivery.

Shared release plans now admit path-only private development members while refusing
unpackageable private dependencies. Owned-tree inventory failures stop maintenance
instead of allowing a partial inventory. Storage retains its three versioned
publishable groups, existing complete gates and tool pins. The tooling adoption
does not change product APIs or formats; the separate Wire
adoption above changes public Rust dependency identities.
