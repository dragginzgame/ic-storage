# Storage 0.65 notes

## [0.65.5] - 2026-11-03

### 🧪 Testing

The installed comparison accepts `BENCH_UPSTREAM_BUCKET_PAGES` (default 128),
allowing matched tests of smaller DFINITY MemoryManager buckets across Map, Set,
Vector, Cell and region controls. Reports retain the selected page count. This
benchmark-only setting does not alter production Storage allocation or defaults.

### 🔧 Changed

Adopt published Platform Runtime 0.19.0 for Wasm backing with only `ic0` enabled,
and Platform/PocketIC 0.19.0 in the independent qualification workspace. Native
production remains free of Platform; default Wasm retains no executor, CDK,
guard, Types or Candid dependency. Public APIs and stored formats are unchanged.
Qualification and comparison clients handle fallible setup, installation, clock
and cycle operations. Rollback checks distinguish canister traps from client
failures. Installed IO, all five collection forms, directory faults, custody,
Logging, upgrades and rollback pass with the retained 16.1.0 server selection.

Map, Set and region mutations encode B-tree nodes into one final record buffer,
then fill the framing length and checksum over that payload. The existing
capacity admission, checksum algorithm and staged root-last publication remain;
persisted frame bytes are unchanged.

Membership searches stop at the matching key without copying its inline value.
Map reads decode inline values directly from the checked node while it remains
alive, avoiding a temporary owned byte buffer for scalar codecs. Codecs returning
owned strings or bytes still allocate their results. External values continue to
use a separate owned, checksummed payload buffer. Bounds checks and codec errors
remain enforced; public APIs, cache budgets and stored formats are unchanged.

## [0.65.4] - 2026-11-02

### 🔧 Changed

Directory mutation now verifies backing, prepares one candidate image, reserves
snapshot capacity and publishes within the same exclusive store borrow. No
prepared candidate escapes to another owner or a later generation. The full base
copy and intermediate indexed candidate are removed; final candidate indexes are
built once after metadata reservation converges. Wire limits bound encoding, and
structural/budget admission still precedes backing growth and writes. Abandoned
tails, inactive snapshot reuse, growth refusal and poisoning retain their contracts.

Release preparation retains the exact source-derived lockfile projection and runs
`cargo fetch --locked --offline` to admit it, replacing `cargo update --workspace`.
Checks still reject unrelated dependency changes and retain failed receipts and
artifacts. Prior attempts must recover on their original source/command plan;
their saved receipts are not rewritten. No executable shared snapshot is changed.

Map, Set and region deletion keep a modified child in memory until its parent
completes underflow repair, and reuse inspected siblings when merging. Final
nodes are encoded for staged publication without an intermediate child record
being encoded and decoded again. Unchanged ancestors remain borrowed. External
value reads keep the framing prefix on the stack and transfer one checked payload
buffer to the codec; replacement/removal reads share this path. Bounds, checksum
admission, pre-commit decoding and root-last publication remain intact.

Public APIs, stored formats and other release groups are unchanged. The pending
root dependency updates are separate work and are not part of these simplifications.

## [0.65.3] - 2026-11-02

### 🔧 Changed

Optional map caching now sizes its slot table from the byte budget instead of
capping every cache at 32 slots. The root and immediate children resist eviction
by deeper nodes; root replacement clears obsolete depth assignments. Actual node
buffer capacities and slot bookkeeping still control admission. Caching remains
disabled initially, and the existing public budget API and stored formats remain.

Mutation traversal retains checked routing views until a node changes. Unchanged
ancestors no longer copy all keys, inline values and child links. Child entry counts
travel back up deletion paths, avoiding redundant rebalance decoding and a final
root read when it remains nonempty. Staged publication, pre-commit value decoding,
growth refusal, integrity checks and shared-owner poisoning remain intact.

### 🧪 Testing

The stateful comparison checks phase-entry existence, absence and previous values
before executing either backend. `RemoveMiss` uses keys disjoint from inserted
keys; growth/shrink precede removal, and reinsertion follows removal. The new
`RemoveInserted` phase cleans up the insertion range, restoring population across
rounds. Repeated hot keys can still yield misses/replacements later within a batch.
`MissAbove` explicitly identifies above-population lookups; access-pattern labels
do not imply interior or below-population misses. Historical outputs retain their
original traces and must not be read as isolated missing-removal/growth benchmarks.

Test-only diagnostics count cache hits, cold/collision misses, protected/budget
refusals and owned-node materialization. Regressions exercise routing retention,
budget accounting and copying only a modified leaf, plus generated mutation,
reopen, live/free overlap and poison coverage. These counters add no production API
or runtime overhead.

## [0.65.2] - 2026-11-02

### 🐛 Fixed

Require published `ic-platform-runtime` >=0.18.1 with default features disabled,
only on Wasm, selecting `ic0` alone. Backing size, growth, reads and writes use
the public safe `stable64_*` wrappers. Growth maps `u64::MAX` to the Memory
trait's `-1` refusal and checked-converts successful previous page counts.
Native production remains free of Runtime; default Wasm no longer activates
runtime, executor, CDK, runtime guard, Types or Candid. Hosts explicitly opting
into execution continue to share the canonical Runtime and its matching guard.

The external default consumer is compiled separately from runtime composition on
native and Wasm. Production graph checks enforce the narrower feature boundary;
installed tests retain IO, bounds traps, growth/refusal, reopen, upgrades and
rollback coverage. This fixes [Platform #135](https://github.com/dragginzgame/ic-platform/issues/135)'s
Storage integration for [Relay #21](https://github.com/dragginzgame/ic-relay/issues/21).
No public API, retained format, reset policy or other release group changes.

## [0.65.1] - 2026-11-02

### 🔧 Changed

`MemoryRuntime::diagnostics()` validates the current backing and returns a bounded
`StorageDiagnostics` summary: generation, retained/admitted allocation counts,
live leases, data extents/pages, reserved directory pages, active snapshot bytes,
physical pages and unassigned pages. It does not open allocations, invoke host
policy or modify backing. Page totals measure capacity, not live payload bytes;
unassigned pages are not promised reclaimable. Hosts retain their own namespace
policy and response framing. The old manager/ledger recovery API is not restored.

Directory preparation accounts for abandoned physical tails directly in its owned
candidate, avoiding a temporary indexed Directory and repeated full-image clones.
Metadata reservation sizing carries the owned image between attempts. Stale-base,
receiving-budget, on-disk verification and final publication checks remain.

B-tree free-block reuse splits larger blocks into the requested size and ordinary
free-list halves. Small nodes/values no longer consume an entire larger freed
block. Replacements needing at most a quarter of their current block reuse an
available smaller block and free the original whole block. Otherwise they retain
capacity: splitting live blocks would defeat reuse under alternating large/small
updates without coalescing. Coalescing is not added. The node, value, free-list
and directory formats remain unchanged.

Maps expose `keys_range(bounds)` without external value reads and
`set_node_cache_budget(bytes)` for optional heap caching. Caching starts disabled;
zero disables it and changing the budget discards cached nodes. Budget accounting
includes retained buffer capacities and cache bookkeeping, excluding allocator
overhead and nodes held by active iterators. External values are not cached.
Mutations invalidate affected nodes, clearing discards the cache, and reopening
starts cold. Region views still reload per operation. Cache hits consult the
governed backing owner so another allocation's failure cannot bypass poisoning.

Read traversal keeps one checksummed record buffer with entry offsets instead of
copying every key and inline value. Mutation staging and integrity admission stay
in place. Inserts/removals avoid writing ancestors whose routing contents did not
change. Fixed-size vector reads combine the slot header and payload in one read;
iterators reuse their decoding buffer. Adjacent IO reuses the last translated
extent, with full-range checks and invalidation at directory publication.

### 🧪 Testing

Generated mutation histories run with disabled, small and larger node caches,
checking an ordered model, cold reopening and disjoint live/free ranges. Failures
are reduced to a smaller replayable operation list. The installed comparison
adds an explicitly isolated upstream Git control pinned to `b5d1650`, alongside
the published 0.7.2 control. It supports selected cases, up to one million rows,
shuffled map/set/region populations, Zipf access, repeated rounds and ordinary-map
cache controls. Supported input size does not imply qualification at that scale.

### 🧹 Cleanup

Remove the unused `ic-testkit-native` development dependency. Published Native
0.80 removes its old memory module; Storage already owns the replacement
`testing::{MeteredMemory, MemoryIoCounts}` helpers and has no allocation-measurement
callers. Hosts using generic allocation measurement can select Native 0.80
independently. The installed Testkit server CLI retains its separate selection.

### 🐛 Fixed

Bounded scans compare candidate keys with the current range before reading
external values. Cursor traversal reads the following subtree only when another
entry is requested; exhausted ranges stop without that prefetch. This prevents
excluded value/subtree corruption from failing an otherwise valid bounded scan.
Corruption still fails traversal when the requested range reaches it. Forward,
reverse, mixed-direction and fused iterator behavior retain the same public API.

## [0.65.0] - 2026-11-02

### ⚠️ Breaking

Public collection/directory codec errors now carry Wire 0.15 rather than 0.14.
Hosts matching or converting those errors must align their direct Wire dependency.
Wire/derive 0.15.0 is published and keeps codec bytes, schemas and budgets unchanged;
its Rust 1.99.1 floor already matches Storage. This supplier adoption adds no
stored-format migration beyond the independent B-tree change below.

Map, Set and map regions now use `ICMAP002`, a degree-six B-tree with up to eleven
entries per node. This replaces the one-entry AVL format. Hosts must explicitly
rebuild or reset affected collection state; region consumers must update their
framing checks. No earlier map format is decoded or automatically reset. Public
Rust types and signatures, allocation governance, Cell and Vector formats remain
unchanged. This work is not a release or consumer migration.

### 🔧 Changed

Routing nodes use checked binary fields rather than generic serialization of
entire key/value records. Values up to 32 encoded bytes remain inline; larger
values live in separate checksummed blocks. Searches do not read unrelated
external values. Membership and key-only scans verify routing records without
claiming to audit stored value integrity. Matching values retain codec-bound and
checksum checks. Iteration keeps bounded routing frames and supports interleaved
forward/backward traversal.

Splits, sibling borrowing, merges and root collapse maintain a balanced B-tree.
Mutations still stage all affected bytes and admit capacity before publication.
In-place replacement skips unchanged routing and allocator/root records. Native
backing failures remain nontransactional and poison the owner; IC traps use host
rollback. The [provenance and ownership note](../../docs/storage/upstreams.md)
distinguishes established algorithmic techniques from Storage's own format.

Shared Tooling advances to committed 0.27.27 (`651f5f7`), Build to 0.74.0,
Host libraries to 0.74.1 and Testkit to 0.79.0. Stable IO now imports Runtime
0.18 only on Wasm, removing Platform/Runtime from native production. Wasm still
requires the runtime feature until [Platform #135](https://github.com/dragginzgame/ic-platform/issues/135)
exposes stable-memory grow/read/write through IC0 alone. The Wasm execution
boundary remains a follow-up; public backing APIs and growth-refusal behavior
are unchanged. Native qualification uses Platform/PocketIC 0.18 with the same
16.1.0 server. Only the unpublished DFINITY benchmark retains Platform 0.17's
removed stable-structures facade. Rust remains 1.99.1. This tooling adoption
changes no Storage format beyond the B-tree change described above.

### 🧪 Testing

Native backing IO metering is available through
`ic_storage::testing::{MeteredMemory, MemoryIoCounts}` with `test-support`.
Consumers can replace Tooling's memory-trait bridge with a wrapper over Storage's
owned `Memory` interface. Physical backing identity is preserved across raw,
wrapped and cloned aliases. Clones share counters and reset; reads/writes count
attempts, growth counts completed calls and successful requested pages, and
overflow is sticky until reset. Reject overflowed counts for exact measurements.
Allocation measurement remains in `ic-testkit-native`. This additive helper
changes no production backing behavior or stored format.

Native coverage checks retained occupancy, separator ordering, equal leaf depth,
unique live blocks, variable-size key/value relocation, repeated split/merge and
reopen cycles, malformed routing/value records and bounded key-only IO.

The installed comparison now includes Cell, Map, Set, Vector and regions with
concrete type cases and model-checked complete results. Additional operations
cover membership, reverse/key scans, payload growth/shrink, missing removal and
reinsertion. DFINITY has no region wrapper; its region control reloads a map view
per operation. Its Set iterator has no reverse API, so that comparison is omitted.
See the [benchmark methodology](../../qualification/ic-storage-benchmarks/README.md).

The expanded matrix has 28 concrete cases / 46 type-size combinations. Signed
integers use an identical fixed-width benchmark wrapper on both backends; wide
keys, long shared prefixes, exact-bit floating-point vectors, 31/32/33-byte fixed
values and 4 KiB variable payloads cover additional layouts. Map first/last
lookups and exclusive-upper-bound scans retain independent model checking.
Summary CSVs now include median physical stable pages for each backend, including
metadata and reserved capacity rather than only live payload.

[Issue #152](https://github.com/dragginzgame/ic-storage/issues/152) is addressed in
source by aligning backing IO with Runtime 0.18 rather than Platform 0.17's
executor. An isolated unpublished consumer composes candidate Storage with the
published Platform 0.18 runtime feature and admits one Runtime and exact guard
on native and Wasm. This alignment does not itself change retained bytes or
require the separate B-tree format change. Published Storage 0.64.0 remains
incompatible until a corrected Storage release is delivered. Removing Wasm
execution features altogether remains separate Platform #135 work.
