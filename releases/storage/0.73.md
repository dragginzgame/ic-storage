# Storage 0.73 notes

## [0.73.2] - Unreleased

### 🔧 Changed

Select published IC Build 0.83.0 for the native repository helper and the
separately installed release metadata editor. Storage does not use the removed
progress wrappers or interval-scheduled maintenance APIs, so its release and
recovery interfaces remain unchanged. Run `make install-release-tools` to prepare
the new editor; ordinary checks continue to admit it offline. Existing tool
caches and release evidence are retained. This development-only change does not
alter collection APIs, stored formats or the production Wasm dependency graph.

## [0.73.1] - 2026-11-11

### 🧪 Testing

Extend native Map scan attribution with entry/key-only controls over 256/4096
records, three start positions, limits 1/32/256 and three payload shapes. Compare
Storage, governed ICSS and ICSS's own manager against an independent value model.
The native release helper adopts Build 0.82; Wasm backing selects Runtime 0.21.1.
Development codecs select Wire 0.21.1 and both workspaces adopt Toko Tooling
0.39.10 through the authenticated installer.
The scan controls qualify the range optimization below; stored formats remain unchanged.

Collection comparison servers now have one bounded hour per run or type shard.
Complete ordinary, populated-record, bulk and boundary recipes exceeded the
former fifteen-minute limit. The existing commands need no new flags;
five-minute request budgets, workload selection and result checks are unchanged.
The [complete comparison record](../../docs/measurements/storage-full-suite-2026-11-10.md)
retains the failures, full retries and reproduction commands.

The new `cell-open` workload retains the allocation owner while timing collection
admission, decode, the requested operation and drop. It covers u64 and byte values
from empty through 1 MiB, restoring the requested size each round before load
controls, then checking growth and shrinkage separately.

### ⚡ Performance

Map replacements no longer rewrite routing metadata when the value's location
and length are unchanged. Small encoded values stay inline in owned scan entries
and point-read buffers, avoiding a separate heap allocation while retaining lazy
decoding and entry ownership after collection mutation or drop.

Ordered cursors now read the next path only when another result is requested.
Limited scans avoid unused lookahead; corrupt children are still checked before
traversal yields them. Public collection APIs and stored formats are unchanged.
The [focused comparisons](../../docs/measurements/storage-scalar-scans-2026-11-11.md#map-hot-path-experiments--2026-11-11)
record instruction and application-size tradeoffs for each change, including the
broader bounded, reverse and rank-iterator matrix.

External Map key/value and Cell load buffers now initialize directly from backing
instead of zero-filling before reading. Length publishes only after successful
IO; admission checks and partial-read panic handling remain. A custom Memory
backend using the default raw-read implementation pays chunked scratch copying;
the governed production backing forwards direct reads.

Matched 1-MiB Map reads fall from 6,021,870 to 4,973,166 instructions (ICSS:
16,151,418), and Cell reopen controls from 5,860,899 to 4,812,207 (ICSS:
4,970,637). Scalar controls are unchanged by this buffer step. Its application
Wasm growth is 440 bytes for Map, 266 for Cell and 10 for all collections.
Together the four retained hot-path changes add 937 all-collection bytes,
remaining within the optimization size budget. See the linked per-step study
for workload scope, small/wide-key controls and code-section sizes.

The transient physical-backing custody registry now uses sorted identities in
a vector instead of a B-tree. Duplicate refusal, native locking, detached-handle
custody and last-owner release are preserved. This registry is independent of
the ordered collection engine and allocation-lease set; stored formats and
public APIs do not change. Many distinct custom backings trade tree updates for
linear vector shifts; the usual IC backing has one identity.

Matched all-collection Wasm falls from 127,027 to 122,139 bytes, and its code
payload from 109,063 to 104,119 bytes. ICSS remains 119,324 / 77,133 bytes.
Of 864 admission samples, 657 are unchanged, 45 improve and 162 increase.
The largest increase is 420 instructions; the largest relative increase is
0.985%. This is a size improvement, not an instruction-speedup claim. See the
[custody experiment](../../docs/measurements/storage-scalar-scans-2026-11-11.md#retained-custody-registry-simplification--2026-11-11)
for all collection sizes, limits and qualification.

Range admission now retains its checked successor/predecessor paths for the
iterator. The first item at a bounded end no longer repeats a root-to-bound
descent. Nonzero rank jumps and unbounded ends retain their lazy traversal.
Public APIs, stored formats, codec handling and corruption checks are unchanged.

For 4,096 scalar records and 32 results, Map scan instructions fall from
773,363 to 760,735 with shuffled insertion (1.6%) and from 372,747 to 201,440
with sequential insertion (46.0%). The shuffled region key scan falls from
504,528 to 335,248 (33.6%). The broader ordered matrix has 252 improved medians,
1,800 unchanged and no regressions. Shuffled Map scans still cost 2.44 times
ICSS; this is a focused improvement, not overall parity.

Size consumers now exercise dynamic Map/region range bounds. On identical
range-aware fixtures, Map-only Wasm adds 197 bytes and all collections add 58.
Each bounded endpoint now retains a path allocation even for count-only or
opposite-end consumption; count-only instruction cost is not separately measured.
See the [experiment](../../docs/measurements/storage-scalar-scans-2026-11-11.md#retained-range-path-experiment).

## [0.73.0] - 2026-11-10

### ⚠️ Breaking

Memory, named backing, Cell, Vector and ordered collections now use independently
implemented Storage engines. Map, Set and map regions share one AVL engine.
Copied ICSS engines and their private codec/address helpers are removed; ICSS
remains only an external qualification reference.

The current formats are STORNAM1, STORCELL, STORVECT and STORMAP1, version 1.
Hosts must explicitly supply fresh/reset whole backing and update application
framing admission. Previous images are rejected without writes. There is no
migration reader, automatic reset or production ICSS fallback. Default control
reservation increases from 15 to 18 Wasm pages. Governed leases, public
successful-call APIs, bounds and native failure poisoning remain enforced.

### ⚡ Performance and known limits

The recorded matched all-collection application shrinks from 141,342 to 126,406
raw Wasm bytes; external ICSS is 119,318 bytes. This is application size, not the
benchmark handler module. The replacement is not a universal performance win.
At 4,096 uniform u64 records, Map Get×32 increases from 934,522 to 1,145,264
instructions and Scan×32 from 326,047 to 773,764; ICSS is 914,982 and 309,902.
Small-record Map capacity increases from 26 to 34 pages. Smaller-map mutations
improve. These selected workloads do not predict whole-application throughput.

All 752 depth rows passed state checks, with 265 instruction regressions against
preceding Storage. The complete type catalogue covered 565 selected cases.
See the [ordered-engine record](../../docs/design/ordered-map-replacement.md)
and [replacement inventory](../../docs/design/independent-storage-replacement.md)
for scope, independent implementation inputs and qualification. Raw historical
`target/` artifacts are no longer present at release preparation; these figures
remain recorded comparisons, not regenerated release evidence.

### 🔧 Tooling and packaging

Adopt Toko Tooling 0.39.7, pinned upstream reference documentation and the
canonical root licence file inherited by all workspace packages. Current product
guides are grouped by topic; historical evidence and prior licence grants remain.
The normal release gates independently qualify source, packages and publication.
