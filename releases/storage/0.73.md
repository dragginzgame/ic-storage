# Storage 0.73 notes

## [0.73.0] - 2026-11-10

### ⚠️ Breaking

Memory, named backing, Cell, Vector and ordered collections now use independently
implemented Storage engines. Map, Set and map regions share one AVL engine.
Copied ICSS engines and their private codec/address helpers are removed; ICSS
remains only an external qualification reference.

The current formats are STORNAM1, STORCELL, STORVECT and STORMAP1, version 1.
Hosts must explicitly supply fresh/reset whole backing and update application
framing admission. Previous images are rejected without writes. There is no
migration reader, automatic reset or production ICSS fallback. Default control
reservation increases from 15 to 18 Wasm pages. Governed leases, public
successful-call APIs, bounds and native failure poisoning remain enforced.

### ⚡ Performance and known limits

The recorded matched all-collection application shrinks from 141,342 to 126,406
raw Wasm bytes; external ICSS is 119,318 bytes. This is application size, not the
benchmark handler module. The replacement is not a universal performance win.
At 4,096 uniform u64 records, Map Get×32 increases from 934,522 to 1,145,264
instructions and Scan×32 from 326,047 to 773,764; ICSS is 914,982 and 309,902.
Small-record Map capacity increases from 26 to 34 pages. Smaller-map mutations
improve. These selected workloads do not predict whole-application throughput.

All 752 depth rows passed state checks, with 265 instruction regressions against
preceding Storage. The complete type catalogue covered 565 selected cases.
See the [ordered-engine record](../../docs/design/ordered-map-replacement.md)
and [replacement inventory](../../docs/design/independent-storage-replacement.md)
for scope, independent implementation inputs and qualification. Raw historical
`target/` artifacts are no longer present at release preparation; these figures
remain recorded comparisons, not regenerated release evidence.

### 🔧 Tooling and packaging

Adopt Toko Tooling 0.39.7, pinned upstream reference documentation and the
canonical root licence file inherited by all workspace packages. Current product
guides are grouped by topic; historical evidence and prior licence grants remain.
The normal release gates independently qualify source, packages and publication.
